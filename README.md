
# MTS Churn Prediction

Проект по прогнозированию оттока клиентов телеком-компании на основе поведенческих и финансовых характеристик абонентов.

Основная цель — построить модель, которая позволяет заранее определить клиентов с высоким риском ухода и использовать прогноз для более точечного проведения retention-кампаний.

## Задача

Задача сформулирована как бинарная классификация:

* `churn = 0` — клиент остался;
* `churn = 1` — клиент ушёл.

Помимо качества классификации, в проекте рассматривается практическое использование вероятностей модели: выбор порога принятия решения и оценка потенциального бизнес-эффекта от работы с группой риска.

## Данные

Используется датасет `mts-churn` с Kaggle.

Размер исходной выборки:

* **20 468 наблюдений**
* **29 признаков**
* целевая переменная — `churn`

В данных представлены:

* демографические характеристики клиентов;
* доход;
* параметры использования услуг;
* качество звонков;
* количество жалоб;
* задолженность;
* параметры контракта;
* длительность и интенсивность использования связи;
* категориальные характеристики клиента.

В текущей версии модели используются **14 числовых признаков**.

В ноутбуке проведён базовый исследовательский анализ данных:

* анализ распределения целевой переменной;
* описательная статистика;

В выборке наблюдается выраженный дисбаланс классов: клиентов с оттоком значительно меньше, чем клиентов без оттока.

## Модель

Для классификации используется:

**CatBoostClassifier**

Основные параметры модели:

```python
CatBoostClassifier(
    iterations=1000,
    learning_rate=0.5,
    depth=8,
    auto_class_weights="Balanced",
    eval_metric="AUC",
    early_stopping_rounds=50,
    random_seed=42
)
```

Данные разделяются на train и test:

```text
Train: 16 374
Test:   4 094
```

Разбиение выполняется со стратификацией целевой переменной.

Для компенсации дисбаланса классов используется:

```python
auto_class_weights="Balanced"
```

Early stopping остановил обучение на **176-й итерации**.

## Результаты

На тестовой выборке модель показала:

| Метрика           |   Значение |
| ----------------- | ---------: |
| ROC-AUC           | **0.9611** |
| Average Precision | **0.9132** |
| Accuracy          |   **0.98** |

Для класса оттока при стандартном пороге классификации:

| Метрика   | Значение |
| --------- | -------: |
| Precision | **0.92** |
| Recall    | **0.85** |
| F1-score  | **0.88** |

Таким образом, модель хорошо разделяет клиентов по риску оттока даже в условиях значительного дисбаланса классов.

## Подбор порога классификации

Помимо стандартного порога `0.5`, в проекте исследуется влияние threshold на:

* Precision;
* Recall;
* F1-score;
* размер группы клиентов, попадающих в retention-кампанию.

На тестовой выборке максимальный F1 достигается примерно при:

```text
threshold = 0.78
```

При этом для класса оттока получены:

```text
Precision: 0.95
Recall:    0.83
F1-score:  0.89
```

Выбор threshold в реальном бизнес-сценарии должен зависеть не только от F1-score, но и от стоимости контакта с клиентом, стоимости пропущенного оттока и эффективности retention-кампании.
